# 视觉页面意图读取

## 读取阶段

先执行 [买点确认与飞轮衔接](buying-point-confirmation.md)。确认前读取通用模板角色和历史有效授权，为买点表达提供容量约束；不产生或批准新的项目视觉计划。正式视觉策划在买点确认且A内价格等原前置齐备后开始，实际页面数量由该阶段的项目方案确定。已确认项目复用当前合同，不重新走新品确认。

## 读取顺序

1. 当前产品已有项目计划/合同及本次范围；锁定页沿用已确认版本。
2. `{skills_root}/ecommerce-visual-designer/SKILL.md` 以及 `{business_root}/视觉基准/Pink & White 电商视觉唯一全局基准.md`。
3. 当前所选 Profile 的 SKILL、架构和生产蓝图。Lolita套组读取 `lolita-set/references/set-template-v2-contract.md`、`set-case-architecture.md`、`set-production-blueprints.md`，路径均相对 `{skills_root}/` 下对应技能目录。单品/轻氛围使用相应 Profile，不把套组页面复制过去。
4. 涉及主图时读取控制器 `references/pnw-wearing-led-main-image-system.md`；角色示例冲突遵循当前全局和 Profile 覆盖合同，记录采用依据。

只做内容策划不必加载渲染实现、启动生图或增加制作审批；开始实际生产时按视觉控制器完整流程执行。

## 当前数量口径（2026-09-21读取，使用时检查变化）

- 主图：正式序列5张；第1、2张各一张Plan B，因此候选7张。A/B承担同一购买职责，以不同镜头/组织表达，不当作新增第6、7个购买环节。
- 详情：Part 1 品牌/穿戴，Part 2 工艺/结构，Part 3 选择/规格/护理/风险。Part 1前两张固定品牌模块必须保留原样。三个部分不是三张图，当前套组合同没有规定通用总张数；按已批准项目清单继承，或提出明确分模块页数的候选。
- 独立规格：按最终销售SKU/档位覆盖清单，不能从主图5抵扣。颜色是否分图以实际合同为准；数量不清时列待定。
- 活动：800×1200全幅，无文案；材质：独立真实微距轨道，不以主图4代替。
- 明确区分页面模块数、实际导出文件数、A/B候选数和独立人物素材池数量；12张等人物源下限不是详情数量。

## 购买链与冲突处理

全局主图链为：看见穿戴结果 → 搭配共鸣 → 第一顾虑证据 → 另一结果/第二顾虑 → 选择与购买信心。消费者不一定依序浏览；每页应独立可懂，又为整组提供新增信息。

套组旧示例里的发带、鞋夹、袜口蕾丝、2/3/4/6件及“省时间”不是所有产品必有。按真实组件替换其证据职责；不能为满足例子增加不存在的商品。蓝图M4“实拍信任”须与当前合同主图1—4穿戴主视觉兼容：穿戴承担首眼，实拍细节承担证明。

正式视觉策划已具备前置条件且页面清单缺失时，形成建议并标明数量是本次方案；买点确认前不把这份建议当作已启动视觉策划。一个消费者问题需多个独立事实页说明时可以展开；没有独立职责的重复页不为凑数添加。已有批准数量不自行删减。
